Gráficas en HTML frente a Python, R, D3 y Plotly

Cuándo usar cada enfoque para gráficas, tablas, esquemas y figuras, con una demostración interactiva

Autor/a

Mauricio Romero Torres

Fecha de publicación

25 de noviembre de 2026

Fecha de última modificación

25 de noviembre de 2026

TipEn resumen
  • No hay que elegir una sola herramienta. Lo más eficiente es repartir el trabajo por capas:
    • Análisis y publicación impresa: ggplot2 o Matplotlib/Seaborn.
    • Gráficas interactivas estándar, desde el mismo código: Plotly, Altair o Highcharter.
    • Piezas a la medida para la web: HTML/CSS/SVG nativo cuando son sencillas; D3 cuando son complejas (narrativa, explicadores, tableros pequeños, esquemas).
  • El HTML nativo es la opción más flexible y liviana. Además, es la que mejor producen los asistentes de IA. Su punto débil es la reproducibilidad: los datos tienen que vivir en archivos versionados, no escritos a mano dentro de la página.
  • Para un sitio en Quarto como este, recomiendo Python o R como base, {=html} u OJS para piezas especiales, y una regla fija: toda cifra visible debe poder rastrearse a un archivo de datos del repositorio.

Por qué volver a esta pregunta

Las publicaciones recientes en redes sobre “pedirle a una IA una diapositiva en HTML” muestran algo que los equipos de ciencia de datos venían viendo: un solo archivo HTML puede tener tablas que se ordenan, gráficos que responden al tacto, esquemas que se recorren paso a paso y controles que recalculan escenarios. Antes, eso exigía D3 o una biblioteca de tableros. Hoy un asistente lo escribe en minutos.

Eso cambia el costo de producir visualizaciones a la medida. Pero no cambia lo que hace confiable una gráfica: datos rastreables, código reproducible y un diseño que no engañe. Este artículo compara los enfoques con ese criterio.

Cuatro familias de herramientas

La frontera entre “HTML” y “otros lenguajes” es más difusa de lo que parece. Plotly, Altair y Highcharter también producen HTML y JavaScript; la diferencia está en quién escribe ese código y desde dónde se controlan los datos.

Familia Ejemplos Qué escribes Qué obtienes
1. Gráficas estáticas Matplotlib, Seaborn, ggplot2 Python o R Imagen (PNG, SVG, PDF)
2. Envoltorios interactivos Plotly (Python/R), Altair, Highcharter, Bokeh Python o R HTML + JS generado automáticamente
3. Gramáticas para la web Observable Plot, Vega-Lite, Quarto OJS JavaScript declarativo HTML + SVG
4. Control total en el navegador D3.js, HTML/CSS/SVG nativo JavaScript, HTML y CSS Cualquier cosa que el navegador pueda dibujar

Dos datos concretos para el contexto institucional:

  • Peso de Plotly. La biblioteca completa de plotly.js pesa cerca de 4,8 MB minificada (unos 1,5 MB comprimida) según su propia documentación de distribución. Existen paquetes parciales más livianos (detalles).

Más allá de las gráficas: tablas, esquemas y figuras

Elemento En Python / R En HTML nativo Comentario
Tablas gt, reactable, DT (R); itables, great_tables (Python) <table> con ordenar, filtrar y barras en celdas Las tablas HTML son el formato más accesible y copiable. Los paquetes de R/Python ya generan HTML de calidad.

El mismo gráfico en cuatro lenguajes

Eventos por mes, en barras. La extensión del código ilustra el compromiso entre conveniencia y control.

  • ggplot2 (R)
  • Plotly (Python)
  • D3.js
  • HTML + CSS nativo
library(ggplot2)
eventos <- read.csv("data/eventos_mes.csv")
ggplot(eventos, aes(mes, n)) +
  geom_col(fill = "#0b6e99") +
  labs(x = NULL, y = "Eventos") +
  theme_minimal()
import pandas as pd
import plotly.express as px
eventos = pd.read_csv("data/eventos_mes.csv")
fig = px.bar(eventos, x="mes", y="n", labels={"n": "Eventos", "mes": ""})
fig.show()   # o fig.write_html("eventos.html")
const datos = await d3.csv("data/eventos_mes.csv", d3.autoType);
const x = d3.scaleBand(datos.map(d => d.mes), [40, 600]).padding(0.1);
const y = d3.scaleLinear([0, d3.max(datos, d => d.n)], [300, 10]);
const svg = d3.select("#grafico").append("svg").attr("viewBox", "0 0 620 330");
svg.selectAll("rect").data(datos).join("rect")
  .attr("x", d => x(d.mes)).attr("width", x.bandwidth())
  .attr("y", d => y(d.n)).attr("height", d => 300 - y(d.n))
  .attr("fill", "#0b6e99");
svg.append("g").attr("transform", "translate(0,300)").call(d3.axisBottom(x));
svg.append("g").attr("transform", "translate(40,0)").call(d3.axisLeft(y));
<div class="barras" id="grafico"></div>
<style>
  .barras { display:flex; gap:4px; height:200px; align-items:flex-end }
  .barras div { flex:1; background:#0b6e99; border-radius:4px 4px 0 0 }
</style>
<script>
fetch("data/eventos_mes.json").then(r => r.json()).then(datos => {
  const max = Math.max(...datos.map(d => d.n));
  document.getElementById("grafico").innerHTML = datos
    .map(d => `<div style="height:${d.n / max * 100}%" title="${d.mes}: ${d.n}"></div>`)
    .join("");
});
</script>

Observa que los cuatro leen los datos de un archivo. Esa es la regla que mantiene confiable cualquier enfoque.

Riesgos de las gráficas HTML hechas a mano o con IA

  1. Datos incrustados sin fuente. Un asistente tiende a escribir los números dentro del código. Si nadie los verifica, la gráfica puede verse impecable y estar equivocada. Regla: los datos van en CSV o JSON versionados, y la página los lee.
  2. Cifras inventadas o “ilustrativas” que se vuelven reales. Toda demostración con datos sintéticos debe decirlo en la misma vista, no solo al pie del documento.
  3. Código difícil de mantener. Cien líneas de JavaScript sin estructura son fáciles de crear y difíciles de modificar. Conviene separar datos, estilo y lógica, y documentar el propósito de cada pieza.
  4. Accesibilidad. Los gráficos SVG necesitan aria-label y alternativas textuales; las tablas HTML reales son preferibles a tablas dibujadas.
  5. Versión imprimible. Informes, artículos y documentos oficiales siguen necesitando una imagen estática o un PDF. Ahí, ggplot2 y Matplotlib siguen siendo la mejor opción.
  6. Seguridad. Una página que inserta texto de fuentes externas con innerHTML puede ejecutar código no deseado. Para datos de terceros, usa textContent o escapa los valores.

Recomendación para el sitio y para la SCR

Situación Herramienta recomendada
Notebook de análisis reproducible (CRC, indicadores, series del IDEAM) ggplot2 o Matplotlib/Seaborn; interactivo con Plotly si se publica en la web
Gráfica interactiva estándar dentro de una página Quarto Plotly (R o Python) u Observable Plot con OJS
Vistas enlazadas (seleccionar en una y filtrar otra) desde Python Altair
Explicador, diapositiva interactiva, esquema que se recorre, tablero pequeño HTML/CSS/SVG nativo, con datos en archivo aparte
Redes, jerarquías, mapas proyectados a medida, transiciones D3.js
Tableros vistosos de series de tiempo Highcharter, solo si la licencia lo permite; si no, Plotly

Demostración: elementos interactivos en HTML puro

Las cuatro piezas siguientes están hechas solo con HTML, CSS, SVG y JavaScript, sin bibliotecas. Todo está en un único archivo de unos 25 KB, frente a los más de 4 MB de plotly.js completo. Los datos son sintéticos y se generan en el navegador con una semilla fija, para que siempre den lo mismo.

  1. Tabla: ordenar, filtrar, buscar, barras en celdas y minigráficos de tendencia.
  2. Esquema: árbol de decisión que se recorre respondiendo preguntas.
  3. Figuras enlazadas: mapa de calor mes × año que controla un gráfico de barras.
  4. Serie temporal: nivel de río con umbrales de alerta, zoom por arrastre, media móvil y lectura día a día.
